# インフラプラグインへの引き渡し契約

本プラグインはバックエンドのプログラムを構築する。Google Cloudを含むクラウド資源、Terraform、ネットワーク、IAM、DBサーバー、キュー、監視基盤、デプロイ基盤の作成・変更は別プラグインへ分離する。インフラ側の具体的なプラグイン名やコマンドが未指定なら、存在するものとして呼ばない。

| 論点 | backend-chiefの成果物 | インフラ側の責務 |
|---|---|---|
| 設定と秘密 | 必要な変数名、型、必須判定、秘密を出さない読込コード | 秘密の作成・保管・配送・ローテーション基盤 |
| DB | Adapter、schema/index migration、接続poolの要件、再試行 | サーバー、ネットワーク、TLS証明、実行アカウント、バックアップ |
| 認証・認可 | トークン検証、主体、業務認可、tenant分離 | IdP/IAMの構成、鍵の配送、サービス間信頼 |
| HTTP | port、health/readiness、信頼proxyの設定受取、キャンセル | LB、Gateway、CORS配置、WAF、TLS終端、レート制御 |
| 非同期 | producer/consumer、ack、冪等性、再処理コード | queue/topic、配送設定、DLQ、スケジューラ |
| 観測 | JSONログ、計装、メッセージコード、診断手順 | 収集・保存・閲覧権限・通知・ダッシュボード構築 |
| 実行と終了 | build command、実行command、signal処理、終了猶予の要求 | 実行環境、配備、スケール、起動/終了の設定 |

## 引き渡す値

接続に必要な機能・許可操作、期待するDB版とengine、整合性に必要な構成、最大pool、処理量、payload上限、終了猶予、非同期期限、保持期間と復旧目標は、必要な項目から案件で確定する。未定値を勝手に本番値として埋めない。資格情報そのものを文書へ入れない。

DB migrationの作成と使い捨て環境での検証は本プラグイン。実環境への適用順序・実行主体・停止条件を引き渡す。アプリ起動時に無条件で本番migrationを走らせない。

ローカルのテスト用DB起動設定はプログラム検証の補助として扱えるが、既存の方法を優先し、永続的なクラウド資源を新規作成して代用しない。アプリ成果物のテストと本番での運用準備の完了は区別する。
