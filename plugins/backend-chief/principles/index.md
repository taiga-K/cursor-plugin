# 判断原則の索引

依頼に関わる原則だけを読む。以下の判断は指定技術をGoの開発へ適用する本プラグインの推奨であり、DDDやクリーンアーキテクチャの公式仕様として扱わない。指定ガイドラインの具体規約は[API](../references/web-api.md)・[ログ](../references/logging.md)を正本にする。

| 原則 | 適用場面 |
|---|---|
| [目的・意思決定](judgment.md) | 要件整理、設計案比較、レビュー。 |
| [業務モデル・集約](ddd.md) | 業務ルール、状態遷移、コンテキストの分割。 |
| [責務・依存方向](architecture.md) | 配置、モジュール追加、外部技術の導入。 |
| [Goの型・エラー・並行処理](go.md) | Goコード全般、goroutine、入力変換。 |
| [永続化・DB選択](persistence.md) | DB導入、Repository、索引、データ形式。 |
| [取引・排他・冪等性](consistency.md) | 複数更新、二重実行、外部副作用。 |
| [認証・認可・データ境界](security.md) | 公開入口、認証、マルチテナント、外部入力。 |
| [API契約・互換性](api.md) | エンドポイント、DTO、HTTPエラー、BFF連携。 |
| [ログ・計装・診断](observability.md) | HTTP、DB、ワーカー、障害調査。 |
| [外部連携・ワーカー・資源管理](reliability.md) | 外部API、非同期処理、バッチ、終了処理。 |
| [性能・容量・負荷](performance.md) | 検索、bulk、キャッシュ、遅延調査。 |
| [移行・依存更新・保守](evolution.md) | DB変更、技術負債、依存更新。 |
| [振る舞い・証拠・完了](verification.md) | 実装完了、修正、レビュー。 |

原則が衝突したら、目的・選択肢・根拠・結果・見直し条件を[共通形式](../references/output-contracts.md)に従って記録する。全原則を毎回チェックすることや、小変更への長文ADRを要求しない。
