# UI部品追加

入力：役割、使用画面、入力・操作・表示状態。
1. [調査](../../assess-frontend/SKILL.md)で既存UI、Astryxの採用版、同じ役割で既に使われている部品を確認する。
2. [Astryx選定手順](../../../references/astryx.md)を実行する。要件を役割・情報構造・状態・操作で書き、テンプレート → ブロック → 部品 → hook の順にMCP `search` を複数の言い回しで実行し、候補2〜3を `get` で読んで比較表を作る。既存部品の合成で足りるかを独自実装より先に判断する。
3. [Atomic原則](../../../principles/atomic.md)で粒度と所有先を決める。合成ならどのFSDモジュールが所有するかを決める。
4. [設計](../../design-frontend/SKILL.md)でprops・操作・フォーカス・エラーの契約と部品選定の記録（ADRの項目：文脈・決定・結果）を定める。
5. [実装](../../implement-frontend/SKILL.md)で選定した部品のAPIを採用版で確定し、部品と使用画面を接続する。`shared/ui` と organisms 以上は、状態（初期・読み込み・空・エラー・無効・部分成功）を網羅する story と必要な `play` を同時に追加する。
6. [検証](../../verify-frontend/SKILL.md)で単体・story・実画面の操作と CI を確認し、[レビュー](../../review-frontend/SKILL.md)で不要な抽象化と選定理由の妥当性を確認する。

出力：部品の契約、選定した部品と落とした候補、分類と理由、story、実画面の証拠、CI URL。未確認APIは推測しない。完了：実際の内容と操作に耐え、単体の見た目だけで終わっていない。選定の記録や必須 story がない部品追加は完了にしない。
